## Function

Phase 4B is the repeatable system that converts Phase 4A's locked, season-level Episode Roadmap entries into full, production-ready episode packages — one package per episode, built later, one at a time, each requiring its own approval before the next begins (Stage 2, not started here). This document itself does none of that conversion. It exists solely to define **the template every future episode package will use** and **the quality bar every completed package must clear** before it counts as production-ready.

**Relationship to Phase 4A's Episode Roadmap, stated once, not restated per field below:** Phase 4A's Episode Roadmap (Section 3 of that document) already gives every episode a Purpose, Beginning, Central Conflict, Character Progression, World Progression, Ending, and Transition. Phase 4B's template does not re-derive or duplicate any of that — it takes each episode's existing Phase 4A entry as its seed and expands it into the finer-grained detail (scene-by-scene breakdown, performance direction, visual/audio/asset requirements, readiness review) that Phase 4A's own season-level scope explicitly left for a later pass.

## Section 2 — Episode Production Template

*A reusable, eight-part structure. Every future episode package (Stage 2) fills in every field below using that episode's own Phase 4A Episode Roadmap entry as its seed, plus whatever additional Locked canon the specific beat requires. Fields are defined generically here — no character, location, or event from The Fracture Protocol is assigned to any field in this section.*

### 2.1 — Episode Identity
- Episode number
- Episode title
- Core purpose (expands Phase 4A's per-episode "Purpose" field into full production framing)
- Narrative objective (what this episode must accomplish within its Movement, per Phase 4A Section 2)
- Emotional objective (what the audience should feel, distinct from what happens)
- Audience experience goal (how this episode should feel to watch, building on Phase 4A Section 1's "Audience Experience")

### 2.2 — Story Structure
- Opening hook
- Setup
- Rising conflict
- Character turning point
- Major reveal or progression
- Climax
- Closing emotional beat
- Cliffhanger

*Expands Phase 4A's per-episode Beginning / Central Conflict / Ending / Transition fields into this finer eight-beat shape — every beat must still resolve to the same Phase 4A entry it's built from; this template adds granularity, not new plot content.*

### 2.3 — Scene Breakdown
Per scene:
- Scene purpose
- Location
- Characters present
- Emotional state (per character present)
- Conflict (specific to this scene, tracing to the episode's Central Conflict above)
- Visual requirements
- Audio requirements
- Production needs

### 2.4 — Character Performance Planning
- Character motivations (per scene, tracing to that character's Locked Phase 2C journey and this episode's own Phase 4A Character Progression entry)
- Emotional progression across the episode
- Dialogue intent (what a line is meant to accomplish, not the line itself — no script is written under this template)
- Body language notes
- Relationship dynamics in play this episode

*Any Emotional Continuity requirement already Locked for a given character (Phase 2E, Section 4, "Character Production Guides") is a hard constraint on this field, not a suggestion — cited there, not restated here.*

### 2.5 — Visual Production Planning
- Required environments
- Character appearances
- Props
- Effects
- Technology
- Lighting
- Cinematic requirements

**All fields in this subsection follow Art Bible authority exclusively** — no lighting, materials, camera-language, or environment-design rule is defined, varied, or overridden by this template. A future episode package cites the relevant Art Bible file(s) directly; it does not restate their content.

### 2.6 — Audio Planning
- Narration needs
- Dialogue priorities
- Sound design requirements
- Music tone
- Emotional timing

*Routes through Phase 3A's own citation to Production OS's Music Production SOP and Studio OS's Music & Audio Standards — no new audio rule is introduced here.*

### 2.7 — Asset Requirements
- Characters (cross-checked against the Asset Registry before any new build, per Production Bible Section 7, routed through Phase 3A)
- Environments
- Props
- Effects
- Reusable assets (checked first against Phase 4A Section 6's season-level asset pool before any new asset is proposed)

### 2.8 — Production Readiness Review
Every completed episode package is evaluated against Section 3, below, before it may proceed into the Phase 3A pipeline's Stage 1 (Planning).

## Section 3 — Quality Standards

*The gate every completed Stage 2 episode package must clear. These are evaluation criteria, not new production rules — each routes to an already-Locked standard rather than defining its own.*

| Criterion | What It Checks | Authority Routed To |
|---|---|---|
| **Canon alignment** | No character motivation, faction philosophy, timeline event, world fact, or relationship contradicts Locked canon. | Master System Prompt, World Bible, Character Bible, Faction Bible |
| **Story alignment** | Every beat traces to its seed entry in Phase 2A.2 and Phase 4A's Episode Roadmap; no beat is invented outside them. | Phase 2A.2; Phase 4A |
| **Character consistency** | Performance planning (Section 2.4) matches each character's Locked Phase 2C journey and any Phase 2E Emotional Continuity requirement. | Phase 2C; Phase 2E |
| **Visual consistency** | Visual planning (Section 2.5) matches Art Bible reference sheets, palette, lighting, and forbidden-elements rules exactly. | Art Bible |
| **Asset readiness** | Every asset in Section 2.7 is either logged in the Asset Registry or explicitly flagged as a new build pending registry entry — no unlogged asset is treated as real. | Production Bible Section 7, routed through Phase 3A |
| **Production feasibility** | The episode package's scene count, asset list, and complexity are achievable within Studio OS's runtime targets and current production capacity. | Studio OS; Phase 3A |

**Hard-stop rule, consistent with Production Bible Section 9's own precedent:** a failing Canon Alignment or Character Consistency result blocks the episode package from advancing to Stage 2 approval — there is no partial-pass path for those two criteria specifically.
