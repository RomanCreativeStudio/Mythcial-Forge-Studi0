## Verification

### Impact on existing Art Bible authority
The Art Bible's own `visual-development-guide.md` states its scope as governing "the visual rendering of The Fracture Protocol, starting with Series 01" and reserves its **[LOCKED]** tier for settled creative/visual-identity decisions requiring "founder/Creative Director sign-off to change" (color meaning, rendering register, forbidden elements — each already re-verified multiple times this session as load-bearing, unchanging facts). The Resolution and Color-Management values decided in `Fracture_Protocol_Concept_Art_Technical_Standard_Decision_v1.0.md` are, by that document's own admission, **derived administrative decisions, not settled creative facts** — the VFX figure is explicitly labeled provisional, and none of the four resolution values has any production validation yet (zero actual concept art has been produced against them). Promoting them to the Art Bible's [LOCKED] tier now would place an admittedly incomplete, unvalidated standard at the same permanence level as the studio's core visual-identity rules.

### Compatibility with Phase 6K.0
Full compatibility either way. Phase 6K.0's own Cross-Reference Authority (§8) was purpose-built to house exactly this kind of technical standard — it already anticipated and flagged the resolution/color-management gap as belonging there. Keeping the standards at the Phase 6K layer is not a workaround; it is the mechanism Phase 6K.0 already provided for this.

### Compatibility with future Character/Environment/Prop/VFX production
Both options are eventually workable, but Option A carries materially lower revision risk. This production's own `Production_OS_v2.0.md` explicitly establishes the precedent that pre-production estimates are provisional until real data exists: *"these are pre-production estimates with no completed episode yet to calibrate against; revise after the first 3 episodes ship."* The same logic applies directly here — these resolution figures have no production data behind them yet, and VFX's own deliverable category (Phase 6A.5) remains formally undefined. Locking them now risks repeating the exact class of problem the rendering-register reconciliation just had to fix: a [LOCKED] document later found to be wrong or incomplete, requiring a corrective Amendment.

### Version-control requirements
Option A remains inside Phase 6K.0's own lighter Revision Rule (reopen-and-append, Founder Review each time, scoped to this one discipline). Option B would place all four resolution values under the Art Bible's own full versioning discipline and [LOCKED]-tier sign-off requirement for every future adjustment — a materially heavier process for values this project's own Production OS precedent already expects to be revised once real production begins.

---

## Selected Authority Location

**Option A — standards remain governed under Phase 6K Concept Art Governance only.** Not promoted to Art Bible Locked Canon at this time.

This does not foreclose future promotion. Once (a) actual Concept Art production has validated these figures against real output, and (b) VFX's own Phase 6A.5 deliverable category is properly defined, a future Founder Directive may revisit promotion to full Art Bible status — that determination is not made here.
