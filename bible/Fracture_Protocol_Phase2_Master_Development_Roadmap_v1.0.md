## 1. Phase 2 Structure

Five development areas, exactly as scoped in the Phase 2 directive, each producing its own document (or document set):

- **Phase 2A — Story Architecture.** The narrative skeleton: main storyline structure, season/arc framework, major progression, beginning/middle/end structure, major turning points, character transformation paths.
- **Phase 2B — Conflict Expansion.** How the Light Order / Night Haven / Ascendant Doctrine / Kael four-part conflict (already fully defined in Phase 1C) plays out at story scale — political instability, civilizational consequences, how it actually affects humanity across the timeline Phase 2A establishes.
- **Phase 2C — Character Journey Development.** Full arc development for Kael, Cassian, Titan, Mira, and the Guardian, expanding the already-compiled Phase 1C foundation (motivation, internal conflict, relationships, legacy) into scene-level and arc-level journeys.
- **Phase 2D — World Expansion.** Locations, civilian life, culture, daily existence, organizations, history, and social structures — making the universe feel lived in, not only built around conflict.
- **Phase 2E — Production Bible Development.** The synthesis layer: story reference documents, episode frameworks, character arc documents, visual development guides, writing standards, and narrative rules — the actual production-facing deliverables.

## 2. Development Order

Sequenced by dependency, not by the order listed in the directive:

**Stage 1 — Phase 2A (Story Architecture).** Goes first because every other area needs a skeleton to attach to: Conflict Expansion needs a timeline to escalate across, Character Journeys need arc points to develop toward, World Expansion needs to know which locations and eras actually matter to the story, and the Production Bible can't synthesize documents that don't exist yet.

**Stage 2 — Phase 2B (Conflict Expansion) and Phase 2C (Character Journey Development), in parallel.** Both depend on Stage 1's skeleton; neither structurally depends on the other, though they will cross-reference heavily (a character's arc point is often a conflict escalation, and vice versa) — recommend developing them in the same working pass rather than fully sequentially, so they stay synchronized rather than needing reconciliation afterward. The sequencing caveat this stage previously carried (closing Phase 1C's open items before Phase 2C) is resolved as of Founder Lock Patch 3 — see the Standing Note above.

**Stage 3 — Phase 2D (World Expansion).** Follows Stage 1 structurally (needs to know where/when the story happens) and benefits from Stage 2 (knows what's narratively load-bearing versus pure flavor) — but is otherwise the most independent of the four content areas and could begin as soon as Stage 1 is approved if the Founder wants it running in parallel with Stage 2 rather than after it.

**Stage 4 — Phase 2E (Production Bible Development).** Last by necessity — it's the packaging and synthesis layer for everything above, not new development in its own right.

## 4. Dependencies Between Documents

- **Phase 2A** depends only on Phase 1A/1B/1C (already Locked/Compiled foundation). No Phase 2 dependency.
- **Phase 2B** depends on Phase 2A (needs the timeline to escalate across) and on Phase 1C's Faction Bible (the conflict's belief/strength/weakness framework is already fixed there — 2B applies it at story scale, it doesn't redefine it).
- **Phase 2C** depends on Phase 2A (needs arc points to develop toward) and directly on Phase 1C's Character Bible and Production Alignment Database (extends, not replaces, the already-compiled motivation/conflict/relationship/legacy material for each character).
- **Phase 2D** depends on Phase 2A (needs to know which locations/eras matter) and is strengthened by, but not blocked by, Phase 2B/2C.
- **Phase 2E** depends on all four of Phase 2A–2D — it cannot meaningfully begin until they exist, since it packages them rather than generating new content.

## 5. Canon Alignment Audit Gates

Per the directive's own requirement, every Phase 2 document is checked against Phase 1A/1B/1C before finalization, using the four-outcome framework as given: **KEEP** (preserve as submitted), **MERGE** (combine with existing material into stronger canon), **REFINE** (improve clarity without changing substance), **REMOVE** (only if genuinely harmful to the foundation — not simply because a stronger idea exists elsewhere). One gate per stage, not one gate for all of Phase 2 at the end — this matches how Phase 1C's own passes were audited incrementally rather than only once at the very end, and catches drift while it's still cheap to fix.

2. Each has passed its own Canon Alignment Audit gate with no unresolved contradictions against Phase 1A, 1B, or 1C.

This criterion is satisfied; kept here as the decision record.

5. An explicit Founder Lock (or equivalent "Approved Canon / Effective Immediately") statement is given for Phase 2 as a whole — consistent with how every other phase in this project has required one explicit word before being treated as final, rather than assumed from silence.
