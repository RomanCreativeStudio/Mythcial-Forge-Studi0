# THE FRACTURE PROTOCOL — PHASE 6A.5: ASSET PRODUCTION STANDARDS

**Classification:** Internal — Governance Document (**LOCKED, effective immediately**)
**Status:** Established 2026-07-15 per "Founder Directive — Phase 6A.5 Asset Production Standards (v1.0)." Establishes the permanent production standards governing every asset created for The Fracture Protocol. This document creates no story content, no screenplay revision, and no canon expansion — it is a permanent production governance document only. **Approved 2026-07-15 following a clean PASS Founder Review & Alignment Audit.**
**Absolute authority:** subordinate to Master System Prompt → Phase 1 → Phase 2 → Phase 3 → Phase 4A/4A.2/4A.3 → Phase 4B → Season One Final Canon Certification → Phase 5 Canon Implementation Lock → Phase 5A → Phase 5A.1 → Phase 5A.2 → Phase 5B.5 → Phase 5C → Phase 6.0 → Phase 6A, in that order.
**Relationship to Phase 6.0 and Phase 6A:** Phase 6.0 established the 13-level Production Authority Hierarchy and the top-level asset governance rules (Creation, Approval, Revision, Conflict, Registry, Versioning). Phase 6A organized the specific asset backlog required by the 36 Approved Screenplays. This document defines the concrete technical and procedural standard every one of those assets must satisfy — it does not alter the backlog, the hierarchy, or any prior rule; it fills in how those rules are executed at the asset level.

---

## Purpose

Define the permanent production standards used for every production asset. This document governs:
- Character Art
- Environment Art
- Props
- Vehicles
- Technology
- Visual Effects
- Audio
- Music
- Storyboards
- Animation Assets

No asset category is exempt.

---

## Asset Authority

Every production asset must originate only from:
- Approved Screenplays
- Approved Asset Registry
- Approved Production Roadmap

Never from:
- Memory
- Previous Drafts
- Character Bible
- World Bible
- Production Packages

Those documents explain intent. Approved Screenplays govern production.

---

## Asset Quality Standard

Every asset must satisfy:
- Canon Accuracy
- Screenplay Accuracy
- Production Readiness
- Version Control
- Naming Standard
- Reuse Optimization
- Pipeline Compatibility

No exceptions.

---

## Asset ID Standard

Every production asset receives a permanent ID.

Examples: `CHR-0001`, `ENV-0001`, `PROP-0001`, `VFX-0001`, `AUD-0001`, `MUS-0001`, `SB-0001`, `ANM-0001`.

IDs never change.

---

## Naming Convention

Every asset must follow: `Category_ID_Name_Version`

Examples: `CHR_0001_Kael_v001`, `ENV_0003_WardStationSeven_v001`, `PROP_0012_WardBadge_v001`.

## Color Management

All production assets must use identical color management. The specific working color space, calibration, and delivery-format profile are to be defined by the Art Bible's own technical standards (per Phase 6.0's Asset Creation Rule, this document establishes that a single, consistent color-management standard is mandatory across every asset category — it does not itself invent a specific profile beyond what the Art Bible already governs; any profile not yet specified there is a flagged, not fabricated, open item).

---

## Resolution Standards

Approved resolutions must be defined for:
- Concept Art
- Storyboards
- Animation
- Marketing
- Final Delivery

Consistent with the Color Management section above, this document establishes that a single defined resolution standard is mandatory for each category — the specific pixel/DPI values for each are to be drawn from Studio OS's own Production Standards where already Locked (e.g., the YouTube banner's already-Locked 2560×1440 canvas), and flagged as an open item wherever no Locked value yet exists, rather than invented here.

---

## File Format Standards

Approved formats must be defined for:
- Working Files
- Export Files
- Archive Files
- Preview Files

As with Resolution Standards, this document mandates that every asset category have a single defined format standard for each of the four file types above; specific format selections follow the same already-Locked-or-flagged discipline (for example, the Brand Asset Production Guide's own vector-master/raster-export convention already sets a precedent this document extends to story-production assets, without inventing a new, unrelated format scheme).

---

## Asset Lifecycle

Every asset moves through:
1. Requested
2. In Progress
3. Review
4. Revision
5. Founder Review
6. Approved
7. Locked
8. Archived

No stage may be skipped.

- Founder Approval
