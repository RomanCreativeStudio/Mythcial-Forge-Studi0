## Correction to a Prior Finding

**The Turnaround Pre-Production plan's Step 3 (Open Canon Audit) overstated this gap and is corrected here, not silently carried forward.** It stated: *"no Locked source defines legwear or footwear for Kael."* A direct, full re-read of `Fracture_Protocol_Phase6B3_Costume_Wardrobe_Visual_Canon_v1.0.md` §2's complete Production Attributes table finds this only half accurate: **Boot Design is in fact already Locked** (quoted in full below). **Only legwear (pants/trousers) remains genuinely undefined.** The prior document is not edited retroactively — this correction stands as the accurate, superseding finding for planning purposes going forward.

## Step 2 — Dependency Audit

Which missing elements are **mandatory** before Front, Side, and Back Turnaround generation can begin — determined only from what each view structurally requires, no solution proposed:

| Element | Mandatory before generation? | Reasoning |
|---|---|---|
| **Legwear (pants/trousers)** | **Yes — mandatory, blocks all three views.** A full-body Front, Side, or Back view cannot omit the character's legs the way a bust-crop still could omit lower-body coverage entirely. With zero Locked definition of cut, style, or construction, any attempt to generate any of the three required views would require inventing this element outright — the same failure mode already directly demonstrated by the rejected first- and second-generation images inventing unauthorized costume/branding content into an undefined space. |
| **Boots** | No — already sufficiently Locked to constrain generation without invention. Exact color/material shade remains an open concept-art-stage decision, the same category already established as non-blocking for hair/skin/height (Phase 6B.2 item 21). |
| **Belt** | No — already sufficiently Locked. |
| **Rank-marker / insignia** | No — not structurally required for any of the three views to exist. The already-Approved Calm-state still omitted it entirely and passed both Stage 1 and Stage 2 review without it; the same omission remains available for the Turnaround. |
| **Itemized utility equipment / accessories** | No — the general Storage Systems/Utility Elements philosophy is sufficient to constrain generation (functional pockets/pouches, no oversized capacity) without requiring an itemized list, the same non-blocking category as the cyan-accent exact-placement item already established. |

**Conclusion: exactly one mandatory blocking gap — legwear/trouser design. It blocks all three required views identically, since none can be generated without some Locked basis for what covers the character's legs.**

---

## Step 3 — Resolution Strategy

For the one mandatory missing element:

**Legwear (pants/trousers) — requires a Founder Design Decision, not Concept Art interpretation or existing-canon clarification.**

Reasoning: this is not a case of an existing statement being ambiguous or under-specified (which would call for "existing canon clarification"), nor a case of a design element already established in principle with only its exact value left open (which is what makes hair/skin/height/cyan-shade legitimately Concept-Art-stage per Phase 6B.2's own explicit delegation). **No field addressing legwear exists at all** — not its cut, not its construction, not even whether it is a separate garment from the jacket or part of a single-piece uniform. Every other costume element with this degree of total absence in this production (the original, now-resolved costume gap across all four principal characters) was historically resolved by a dedicated Founder Directive establishing new Locked Costume Canon (Phase 6B.3 itself), not left to concept-art interpretation. This item is classified the same way: a genuine costume-design decision requiring Founder authorization, most naturally delivered as a reopen-and-append addition to Phase 6B.3 §2 (a new "Legwear Design" row, matching the existing Boot Design/Belt Design/Collar Design pattern) — **not decided, drafted, or recommended in any specific form here**, per this directive's own "do not invent solutions" and "do not resolve any item" instructions.

The two non-mandatory open items (rank-marker/insignia; itemized utility equipment) are re-confirmed in their prior classification and require no new resolution-strategy determination here, since Step 2 found them non-blocking.

---

## Step 4 — Production Impact

**Fully Blocked.**

All three mandatory Turnaround views (Front, Side, Back, per `Fracture_Protocol_Character_Turnaround_Production_Standard_v1.0.md`) require some depiction of Kael's legs, and no Locked source defines what that depiction should show. This is a single gap, but it is total with respect to the current required deliverable set — there is no view among the three that could be generated in compliance without it. This is the **only** remaining blocker: the Character Turnaround Production Standard already resolved view-count, layout, naming, and coverage-scope questions in the prior directive, and this audit finds every other lower-body element (boots, belt, general utility philosophy) already sufficiently Locked, and the rank-marker gap already established as safely omittable, consistent with the Approved Calm-state still's own precedent.
