# THE FRACTURE PROTOCOL — PHASE 5A: SCREENPLAY PRODUCTION FRAMEWORK

**Classification:** Internal — Process Document (**Approved — Founder Locked for Production Use**)
**Status:** Compiled 2026-07-15 per "Founder Directive — Phase 5A Screenplay Production Framework (v1.0)." This document establishes the permanent screenplay production standard for The Fracture Protocol — Season One: the production format, writing standards, review process, and screenplay structure every Phase 5B screenplay (Episodes 1–36) must follow. It is the Phase 5 equivalent of `bible/Fracture_Protocol_Phase4B_Episode_Production_Development_Framework_v1.0.md` — a template and standard, not a screenplay itself. **Approved 2026-07-15, following the clean PASS result of its own Founder Review & Alignment Audit.** Status: **Approved — Founder Locked for Production Use**. Per the authorizing directive's own Success Criteria, Phase 5A is now complete and certified ready for use across all 36 episodes — Phase 5B may now begin with Episode 1.
**Function:** Defines *how* every screenplay is structured and produced. Does not write, imply, or pre-determine any episode's actual scene content, dialogue, or story beats — those are supplied exclusively by each episode's own Approved Phase 4B Production Development Package (Episodes 1–36, all Approved — Founder Approved for Production) when each individual screenplay is built in Phase 5B.
**Absolute authority, per the Canon Hierarchy Locked in Phase 5 (`bible/Fracture_Protocol_Phase5_Canon_Implementation_Lock_v1.0.md`):** Master System Prompt → Phase 1 (Core Canon) → Phase 2 (Narrative Architecture) → Phase 3 (Production Bible) → Phase 4A/4A.2/4A.3 (Episode Frameworks) → Phase 4B (Approved Production Development Packages) → Season One Final Canon Certification → Phase 5 Canon Implementation Lock. This document sits below all eight and may not modify or expand any of them.
**Critical Canon Protection Rule, verified throughout:** this framework introduces zero new canon, zero new characters, zero new lore, zero new story beats, and zero screenplay content of any kind. It is a structural standard only, exactly as its own directive states ("Phase 5A does not create canon").
**Asset Registry note, carried forward from the Season One Final Canon Certification Report's own Section 8 finding:** the Asset Registry (`documentation/Asset_Registry.md`) currently logs only `BRAND_ASSET` entries (Mythic Forge Studios brand/logo assets) and contains no entries for any Fracture Protocol character or environment production asset (Kael, Cassian, Mira, the Guardian, Titan; Ward Station Seven, the reconstruction environment, and all other reused locations). Per this framework's own Asset Integration rule ("If an asset does not exist: Flag it as Asset Creation Required. Do not invent or redesign it inside the screenplay"), every Phase 5B screenplay's Section 5 (Asset Requirements) must flag every character and environment asset it uses as **Asset Creation Required** until the Asset Registry gap is closed by a separate, non-screenplay production action — this framework does not close that gap itself, and no screenplay may invent a registry entry to work around it.

## Section 1 — Screenplay Objective

Each screenplay must translate approved canon into a production-ready cinematic script. Every screenplay must preserve:

- **Story continuity** — matching its Phase 4B episode package's Story Structure exactly.
- **Character integrity** — matching the Character Bible and each character's established Phase 4B Character Performance Planning.
- **Canon accuracy** — introducing no fact, event, relationship, or world detail beyond what Phase 1–4B already establish.
- **Emotional progression** — matching each episode's own Phase 4B Emotional Objective and Character Performance Planning entries.
- **Production efficiency** — remaining feasible within Studio OS's Mainline Episode runtime target, using only assets already logged (or explicitly flagged as Asset Creation Required, per the note above).

---

## Section 2 — Standard Screenplay Structure

Every screenplay shall contain the following twenty sections, in this order:

1. **Cover Information** — title, episode number, working title placeholder (matching the Phase 4B package's own title field, still flagged non-final), classification, status.
2. **Episode Metadata** — arc, movement, runtime target, screenplay version.
3. **Canon References** — the specific Phase 4B episode package (sole seed authority for story content) and any Locked Phase 1–2 documents that package itself cites, listed by exact document and section.
4. **Production Notes** — scope flags carried forward from the Phase 4B package's own Production Notes and Scope Flags, restated for screenplay-specific discipline (see Section 6, below).
5. **Asset Requirements** — every character and environment asset the screenplay uses, cross-checked against the Asset Registry; any unlogged asset flagged **Asset Creation Required** (Section 9, below).
6. **Cast List** — every character appearing, cross-referenced to the Phase 4B package's own Character Performance Planning section.
7. **Location List** — every environment used, cross-referenced to the Phase 4B package's own Visual Production Planning section.
8. **Scene List** — a numbered index of every scene, matching the Phase 4B package's own Scene Breakdown one-to-one (same scene count, same scene purposes — a screenplay may not add, remove, split, or merge scenes relative to its Approved Phase 4B package without a Founder Directive authorizing the change).
9. **Full Screenplay** — the scene-by-scene script itself, per the Scene Format (Section 3, below).
10. **Audio Direction** — expanding the Phase 4B package's own Audio Planning section into scene-level direction; introduces no new audio requirement beyond what that section already established.
11. **Music Direction** — same relationship to the Phase 4B package's Music Tone field.
12. **Camera Direction** — expanding the Phase 4B package's own Cinematic Requirements (Visual Production Planning) into scene-level shot guidance; a directorial-interpretation layer (Section 7, below), not a canon layer.
13. **Animation Direction** — feasibility and sequencing guidance only; introduces no new visual canon.
14. **Lighting Direction** — expanding the Phase 4B package's own Lighting field (Art Bible `lighting-system.md` routing) to scene level.
15. **Visual Effects Direction** — states explicitly where no new effect is required (the default, per every Phase 4B package's own Visual Production Planning "Effects: None required" fields to date) or flags any effect the Phase 4B package itself already specified.
16. **Editing Direction** — pacing and transition guidance consistent with the Phase 4B package's own Story Structure beats.
17. **Continuity Checklist** — explicit cross-check against the immediately preceding and following episodes' own Beginning State / Ending Beat, per the Season One Final Canon Certification Report's own Section 2 (Episode Continuity) methodology.
18. **Canon Verification** — the Section 6 checklist below, completed in full for this specific screenplay.
19. **Production Readiness Review** — evaluated against this same six-criterion structure used throughout Phase 4B (Canon alignment, Story alignment, Character consistency, Visual consistency, Asset readiness, Production feasibility).
20. **Founder Approval Section** — Classification/Status header promotion, applied only as a separate commit from the Compile commit, exactly as every Phase 4A/4A.2/4A.3/4B document in this project has been approved.

## Section 3 — Scene Format

Each scene shall include, in this order, the following scene header fields:

- Scene Number
- Scene Title
- INT./EXT.
- Location
- Time of Day
- Story Purpose
- Emotional Purpose
- Characters Present
- Required Assets
- Required Audio
- Required Visual Effects
- Continuity Requirements

Followed by the scene body, in this order:

- Action
- Dialogue
- Performance Notes
- Camera Notes
- Lighting Notes
- Sound Notes
- Transition

Every scene header field above must trace directly to its corresponding Phase 4B package's own Scene Breakdown entry for that scene (Purpose, Location, Characters present, Emotional state, Conflict, Visual requirements, Audio requirements, Production needs) — the screenplay expands each field into shootable detail; it does not add a field's worth of new content unsupported by the package.

---

## Section 4 — Dialogue Standard

Dialogue must:
- Reflect only approved characterization, per the Character Bible and each episode's own Character Performance Planning "Dialogue intent, not lines" fields.
- Advance the approved story — no scene, exchange, or line may introduce a story beat absent from the episode's own Phase 4B Story Structure.
- Avoid exposition that creates new lore — a character may reference already-Locked facts; a character may never state a new fact about the world, their own history, or another character that isn't already Locked somewhere in Phase 1–4B.
- Preserve each character's established voice — consistent with the Character Bible's own characterization for each of the five principal characters (Kael, Mira, the Guardian, Titan, Cassian) and any supporting/institutional presence as scoped by the relevant episode package.
- Support visual storytelling instead of replacing it — action and behavior should carry weight the Phase 4B package's own "Dialogue intent, not lines" fields explicitly reserve for behavior, not dialogue.

This standard is the direct screenplay-stage continuation of the Phase 5 Canon Implementation Lock's own Dialogue Rule ("Dialogue may never change a character's established beliefs, motivations, or development. No dialogue may introduce new canon.") — restated here at production-format specificity, not altered.

---

## Section 5 — Cinematic Standard

Every screenplay should prioritize: visual storytelling over exposition; character behavior over explanation; emotional clarity; clear pacing; efficient scene transitions; animation feasibility. These priorities implement, at screenplay scale, the same discipline the Phase 4B framework's own Quality Standards (Section 3) already established for production packages — carried forward, not redefined.

---

## Section 6 — Canon Verification (required for every screenplay before Founder Approval)

Before approval, verify:
- Every scene traces to approved canon.
- Every dialogue exchange reflects the Character Bible.
- Every story beat exists in the corresponding Phase 4B package.
- No protected mystery is altered (Guardian origin/purpose/true-nature; Mira's Arc Three mechanism where applicable; Cassian's extremist-incident specifics where applicable — per each element's own Locked deferral).
- No unsupported lore is introduced.
- No milestone is moved (per the Season One Final Canon Certification Report's own Section 3 milestone-exclusivity findings — e.g., Kael's flaw/synthesis convergence and Cassian's self-dismantling remain exclusive to Episode 35's screenplay; the Guardian's transformation completing remains exclusive to Episode 32's screenplay; and so on for every milestone the Certification Report verified).

---

## Section 7 — Production Annotation Standard

Production notes must distinguish between:
- **Canon requirements** — mandatory; traced directly to a Phase 4B package field or a Locked Phase 1–2 document.
- **Directorial interpretation** — camera, editing, and performance suggestions that serve the canon requirement without themselves being canon (e.g., a specific camera angle achieving an already-Locked emotional beat).
- **Animation guidance** — feasibility and sequencing notes, non-binding beyond production efficiency.
- **Audio guidance** — tone and mix suggestions serving an already-Locked Music Tone or Sound Design Requirement field.
- **Optional production suggestions** — explicitly marked as such; never treated as a requirement.

**Only canon requirements are mandatory.** This distinction must be visually or structurally clear in every screenplay (e.g., via labeled subsections), not left implicit.

---

## Section 8 — Asset Integration

Every screenplay must reference existing assets from the Asset Registry (`documentation/Asset_Registry.md`). If an asset does not exist in the Registry:
- Flag it as **Asset Creation Required.**
- Do not invent or redesign it inside the screenplay.

Per this document's own header note (above), this currently applies to **every** Fracture Protocol character and environment asset used in Phase 5B, since none are yet logged in the Asset Registry outside the `BRAND_ASSET` category. Each Phase 5B screenplay's Section 5 (Asset Requirements) will therefore carry a full **Asset Creation Required** flag list until a separate, non-screenplay production action closes that registry gap — this is expected, standing behavior under this framework, not a defect specific to any one episode's screenplay.

## Section 9 — Screenplay Audit (Founder Review & Alignment Audit structure for every screenplay)

Each screenplay shall receive a structured Founder Review containing the following ten sections, each concluding with **PASS / PASS WITH OBSERVATIONS / FAIL**:

1. Repository Verification
2. Canon Integrity
3. Story Continuity
4. Character Integrity
5. Dialogue Review
6. Cinematic Review
7. Asset Review
8. Audio/Visual Review
9. Production Readiness
10. Final Certification

This mirrors, at screenplay scale, the same audit rigor applied throughout Phase 4A.3/Phase 4B (full reread, repository verification, grep verification, source-quote verification) — restated here as the Phase 5B-specific ten-section structure this directive itself specifies.

---

## Section 10 — Approval Workflow (per episode, restated for Phase 5B)

For every episode's screenplay:
1. Build screenplay.
2. Perform self-verification.
3. Run Founder Review & Alignment Audit (Section 9, above).
4. Resolve any blocking issues (or halt and report if a Missing Canon Rule stop condition is triggered — Phase 5 Canon Implementation Lock).
5. Apply Founder Approval.
6. Commit (separate from the Compile commit).
7. Push.
8. Verify clean repository.
9. Continue automatically to the next screenplay unless a blocking issue is encountered or the Founder issues a new directive.

This is the Phase 5B application of the same Continuous Automated Pipeline discipline already established and repeatedly exercised throughout Phase 4B (Episodes 13–36) — carried forward unchanged in structure, applied now to screenplay production instead of production-package compilation.

---

## Section 11 — Development Order (restated, not altered)

Phase 5B proceeds through Episodes 1–36 in the same order Phase 4B's own Development Order established: Episodes 1–12 (Season One / Arc One), Episodes 13–24 (Arc Two), Episodes 25–36 (Arc Three). Each screenplay's sole seed authority is its own already-Approved Phase 4B Production Development Package — nothing is resequenced, and no episode's screenplay may be written before an earlier episode's screenplay in this order without an explicit Founder Directive authorizing the change.
