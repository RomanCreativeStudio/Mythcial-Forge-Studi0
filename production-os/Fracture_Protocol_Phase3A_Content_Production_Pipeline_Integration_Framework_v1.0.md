## Section 1 — Content Strategy Framework: Why a Story Enters Production

Before any story enters the pipeline below, it must be able to answer: *why does this story deserve to exist, and what does it cost or reward the audience to watch it?* This is a synthesis layer specific to this document — it is not restated from, and does not compete with, any existing document — but it draws its standard directly from what is already Locked:

- Every story produced under this framework must reinforce at least one of the six Locked franchise themes (`bible/Fracture_Protocol_Phase2_Founder_Closure_Statement_v1.0.md`, Section 6) and contradict none of them.
- Every story must trace to the Central Story Question or one of its five-force interpretations (`bible/Fracture_Protocol_Phase2A_Story_Architecture_v1.0.md`) if it touches mainline canon; side content not tied to the mainline arc still may not contradict it.
- Company-level creative philosophy, originality standards, and long-term vision are owned by Studio OS Sections 1, 2, and 5 (**[LOCKED]**) — referenced here, not restated.

**Gate:** a story concept is not "Approved" and ready to enter Section 2's pipeline until it can point to a Locked theme, a Locked story element, or an explicit new Proposal Vault entry authorizing it.

**Where ideas originate:** ideas currently originate through `studio-os/Studio_OS_v1.0.md`, Section 25 (Weekly Sprint Planning, **[LIVING SECTION]**), before entering the gate above. No standalone Idea Management framework exists yet; if one is created in the future, this document should route to that authority instead of Section 25.

## Section 2 — Episode Production Pipeline: End-to-End Workflow, Handoffs, and Department Map

**Authoritative source, in full:** `production-bible/Fracture_Protocol_Production_Bible_v1.1.md`, Section 3 (Production Pipeline, **[LOCKED spine]**) and Section 2 (Studio Organization, **[LOCKED hierarchy]**). This section only maps the handoffs between them; it does not restate their content in operative form.

**The pipeline, at the level a new collaborator needs to see it move end to end:**

| Stage | Role that owns it (Production Bible Sec. 2) | Gate to next stage (Production Bible Sec. 3) |
|---|---|---|
| 1. Planning | Production Manager | Brief traces cleanly to its concept, no open canon question |
| 2. Scripting | Writer(s) | Script passes canon check |
| 3. Storyboarding | Storyboard Artist | Every script beat has a corresponding shot |
| 4. Asset Production | Animation/Asset Lead | Registry checked before any new build |
| 5. Image Generation | Animation/Asset Lead | Originality Check passed; matches reference sheets |
| 6. Animation | Animation/Asset Lead | No off-model drift within or across shots |
| 7. Voice | Voice Lead | Matches documented speech style |
| 8. Music | Audio Lead | No unlicensed or soundalike material |
| 9. Editing | Editor | Runtime and pacing within target |
| 10. Quality Assurance | QA Owner | Full checklist passed (Section 4, below) |
| 11. Publishing | Publishing/SEO Owner | Correct format, metadata, schedule |
| 12. Archiving | Production Manager | Logged per Production Bible Section 14 |

**Handoff rule (restated from Production Bible Section 3, not altered):** no stage begins before the prior stage's gate condition is met and recorded. A role never starts the next stage's work — that is the next role's job, even when one person currently holds both roles (Production Bible Section 2).

**On Studio OS Section 13:** Studio OS's own "Production Workflow" section presents an 8-stage, company-policy-level summary of this same pipeline (Concept → Script → Storyboard → Voice → Animation/Art → Edit → QA → Publish). Per the Governance Manual's Document Authority Hierarchy (Section 3), the Production Bible holds sole jurisdiction over the pipeline's stage *sequence* and gates; Studio OS Section 13 is a higher-level company-policy view of the same sequence, not a second, competing definition of it. Where the two appear to diverge in granularity, the 12-stage sequence above is authoritative.

**Canon-touching work mid-pipeline:** if any stage surfaces a canon question the Bibles don't already answer, the pipeline stops for that item and routes to the Proposal Vault (Master System Prompt Section 12, Rule 5) exactly as Production Bible Section 10 (Risk Management) requires. Production continues only on parts unaffected by the open question.

## Section 4 — AI Production Workflow Integration

AI-assisted production touches three existing authorities, each already governing its own layer; this framework only shows how they hand off to one another:

- **Visual generation standards** (prompts, camera language, lighting, materials, forbidden elements, global consistency): `mythic-forge-art-bible/` — all ten files **[LOCKED]**. Owns every rule for Stage 5 (Image Generation) and Stage 6 (Animation) in Section 2's table.
- **Asset reuse and registry discipline**: `production-bible/Fracture_Protocol_Production_Bible_v1.1.md`, Section 7 (Asset Management) — governs Stage 4 (Asset Production): existing assets are checked in the registry before any new generation is attempted.
- **Department-level operating detail** (prompt troubleshooting, tool-specific SOPs, time estimates): `production-os/Production_OS_v2.0.md`, within its department-level SOP scope per the Governance Manual's Document Authority Hierarchy (Section 3).

This framework does not define a new AI rule, a new prompt standard, or a new originality check. It states only the handoff: any AI-generated output is checked against the Art Bible's rules for its asset type, logged per Production Bible Section 7, before it can pass Stage 5/6's gate in Section 2, above.

## Section 5 — Quality Control Framework: Checkpoints

**Authoritative source, in full:** `production-bible/Fracture_Protocol_Production_Bible_v1.1.md`, Section 9 (Quality Assurance, **[LOCKED]**) — the five-category checklist (Canon Consistency, Visual Consistency, Prompt Accuracy, Continuity, Exports, Documentation) that gates Stage 10 in Section 2's table, above, and Section 11 (Creator Review Workflow, **[LOCKED]**), which governs how a Revision Requested outcome is issued and re-reviewed.

**Hard-stop categories (restated from Production Bible Section 9, not altered):** a failing Canon Consistency or Forbidden Elements check blocks the next stage gate outright — there is no "fix it after publish" path for those two categories specifically.

**On Studio OS Section 14:** Studio OS's "Quality Assurance Checklist" is a company-level, pre-publish-facing checklist covering largely the same ground (originality, canon contradiction, naming, audio, thumbnail, SEO, spelling, final read-through). It operates as a final company-policy pass immediately before Stage 11 (Publishing) in Section 2's table — it does not replace, and is not senior to, Production Bible Section 9's five-category framework, which remains the authoritative QA gate for Stage 10.

This framework defines no new checklist item and alters no existing one.
