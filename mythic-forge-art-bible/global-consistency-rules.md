# Global Consistency Rules
### Mythic Forge Art Bible v3.0

**Governs:** the master rules that apply across every file in this Art Bible, and how conflicts between documents (or between a document and a production impulse) are resolved. Subordinate to `bible/Fracture_Protocol_Master_System_Prompt_v1.1.md` in all cases.

---

## What Must Never Change **[LOCKED]**

1. **Render register.** Semi-Realistic Anime Cinematic Hybrid (`visual-development-guide.md`) is the only sanctioned register, for both animated footage and promotional stills. No shot or still may shift to a different medium (e.g., flat cel-shading, photoreal hyperrealism) without a documented, deliberate, founder-approved exception logged here.
2. **Layer-to-palette assignment.** The megacity's three-color system (`color-language.md`: black/charcoal, cyan/icy-blue, white) is permanent and universal — no zone or character introduces a competing palette system.
3. **System effects always cost something visible.** This is enforced simultaneously by `system-interference-visual-rules.md` (the visual rule) and the World Bible (the narrative/mechanical rule) — the two must never drift out of sync.
4. **The Root Artifact Exception is the only realism exception.** No other object category may claim "too-perfect" material treatment (`materials-and-textures.md`) — if it isn't a Root Artifact, it shows wear.
5. **Character Reference Sheets are the single source of truth.** Once a named character's Reference Sheet exists (Production OS Section 11), no shot may reinterpret their color, proportions, or material spec. A needed change goes through the sheet first, never through a one-off shot decision.
6. **No magic exists.** Every visual reads as system interference, data corruption, or perception/emotional instability (Master System Prompt, System Rule 3) — never as fantasy magic.

## Conflict Resolution **[LOCKED]**

| Conflict | Resolution |
|---|---|
| This Art Bible vs. a production impulse ("it would look cooler if...") | This Art Bible wins, unless changed through the Review Workflow below |
| Two files within this Art Bible appear to disagree | Treat as a documentation bug — flag immediately, do not guess which one is "more right" |
| This Art Bible vs. Master System Prompt / World Bible / Series Bible on a point of *meaning* (not visuals) | The Master System Prompt/World Bible/Series Bible wins — this document only governs *how* canon is rendered, never *what* it means |
| This Art Bible vs. Studio OS or Production OS on a *process* question | Studio OS / Production OS win — this document is not a process document |

## Cross-Document Enforcement **[LOCKED]**

A change to any **[LOCKED]** rule anywhere in this Art Bible requires the same Canon Change process used for world canon (Studio OS Section 18, Knowledge Base Section 34): proposed as a draft, checked against the Master System Prompt's Consistency Enforcement System for contradiction, and signed off by the Creative Director before it takes effect. A version bump and changelog entry (per file) follows automatically once approved.
